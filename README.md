# Lab5

Лабораторная работа №5 (Граф видимости и алгоритм Дейкстры): приложение на C# (Windows Forms) для планирования маршрута мобильного робота на карте с полигональными препятствиями.

Проект реализует полный цикл навигации: от загрузки карты и построения пространства конфигураций с учетом габаритов робота до построения графа видимости, поиска оптимального пути алгоритмом Дейкстры и экспорта навигационных команд в CSV.

Основные возможности:
-Загрузка и отрисовка карт: Чтение полигональных препятствий из текстового файла, парсинг координат с поддержкой разных локалей (InvariantCulture), отрисовка с инверсией оси Y (декартова система координат переводится в экранную).
-Интерактивная установка точек: ЛКМ задает стартовую точку, ПКМ — финишную. Дублирующий ввод координат через текстовые поля с валидацией границ карты.
-Визуализация робота: Отрисовка корпуса (оранжевый круг) и вектора курса (стрелка) с расчетом направления через тригонометрические функции и учетом инверсии оси Y.
-Пространство конфигураций (C-Space): Попиксельное построение «раздутой» карты препятствий с учетом физического радиуса робота. Зеленая зона — безопасно, красная — запретная. Переключение между обычной картой и C-Space в реальном времени.
-Граф видимости: Автоматический сбор узлов (вершины препятствий + старт + финиш), построение матриц смежности и видимости. Поддержка двух режимов проверки ребер: обычный (проверка пересечения) и C-Space (проверка безопасного расстояния).
-Поиск пути (Дейкстра): Реализация алгоритма Дейкстры с поддержкой штрафного коэффициента (×1.5) за движение вблизи препятствий, что стимулирует выбор более безопасных маршрутов.

Трехшаговая визуализация:
-Все связи — полная «паутина» между узлами.
-Только видимые связи — валидный граф без пересечений.
-Найденный путь — красная траектория + оранжевая подсветка препятствий, с которыми робот контактирует.
-Экспорт маршрута: Расчет компасного курса (0° = Север, по часовой стрелке), углов поворота и расстояний между путевыми точками. Сохранение в формате {номер, угол, пробег, X, Y, курс} через диалоговое окно SaveFileDialog.

Реализованные алгоритмы:
-Построение пространства конфигураций (C-Space)
-Вместо приближенной проверки по сетке реализована точная геометрическая проверка для каждого пикселя карты:
-Перевод пиксельных координат в метрические.
-Проверка попадания точки внутрь исходного препятствия алгоритмом трассировки луча (IsPointInPolygon).
-Если точка снаружи — вычисление расстояния до каждой грани каждого препятствия методом DistancePointToSegment.
-Если Distance < R_robot, пиксель помечается красным как часть запретной зоны. Это гарантирует, что центр робота физически не сможет приблизиться к стене ближе, чем на свой радиус.
-Алгоритм трассировки луча (IsPointInPolygon)
-Горизонтальный луч из проверяемой точки пересекает границы полигона. Нечетное количество пересечений означает «внутри», четное — «снаружи». Работает для любых полигонов, включая вогнутые.
-Расстояние от точки до отрезка (DistancePointToSegment)

Точная геометрическая проверка через параметризацию отрезка:
d = W - V
t = ((P - V) · d) / (d · d)
t_clamped = clamp(t, 0, 1)
Q = V + t_clamped · d
dist = |P - Q|
Если проекция точки падает за пределы отрезка (t < 0 или t > 1), расстояние вычисляется до ближайшего конца (угла препятствия). Это исключает ложные срабатывания при диагональном приближении к углу.

Проверка пересечения отрезков (SegmentsIntersect)
Два отрезка пересекаются тогда и только тогда, когда концы первого лежат по разные стороны от линии второго И концы второго лежат по разные стороны от линии первого. Проверка через векторное (косое) произведение в методе Direction:
Direction(Pi, Pj, Pk) = (Pk.X - Pi.X)·(Pj.Y - Pi.Y) - (Pj.X - Pi.X)·(Pk.Y - Pi.Y)

Граф видимости и матрицы (BuildGraphMatrices)
Для каждой пары узлов (i, j) вычисляется:
-Матрица смежности — евклидово расстояние DistanceBetween.
-Матрица видимости — булево значение, определяющее допустимость ребра.

В режиме C-Space вызывается IsSegmentSafeInCSpace, который:
-Отсекает ребра, проходящие сквозь препятствия (SegmentIntersectsObstacle).
-Проверяет расстояние от начала, середины и конца отрезка до всех граней.
-Игнорирует «законные касания» — когда конец пути совпадает с вершиной препятствия (IsPointsEqual).

Алгоритм Дейкстры (Dijkstra)
Классическая реализация поиска кратчайшего пути во взвешенном графе. Сложность: O(V²) для реализации без очереди с приоритетом.
Три массива состояния:
-dist[] — минимальное известное расстояние (инициализация: ∞, кроме старта = 0).
-prev[] — предшественник в оптимальном пути (инициализация: -1).
-visited[] — флаг окончательной обработки узла.
На каждом шаге выбирается непосещенный узел u с минимальным dist[u], помечается как обработанный, и для всех видимых соседей v выполняется релаксация:
newDist = dist[u] + cost(u, v)
if newDist < dist[v]:
dist[v] = newDist
prev[v] = u

Штраф за близость к препятствиям: Если середина ребра проходит ближе 0.1 м к любой стене, его стоимость умножается на 1.5. Это заставляет алгоритм предпочитать более длинные, но безопасные пути через центр свободной зоны.

Восстановление пути: Обратный проход от финиша к старту по массиву prev[] с последующим реверсом списка.

Определение контактных препятствий: После нахождения пути каждый его сегмент анализируется на расстояние от середины до стен. Если Distance ≤ R_robot + tolerance, индекс препятствия добавляется в список touchedObstacles для оранжевой подсветки.
